# Security

Report a suspected vulnerability (for example an authorization or scope bypass,
credential exposure, or an unintended write) through
[private vulnerability reporting](https://github.com/oscscull/baseddsl/security/advisories/new).
Do not open a public issue for it.

Include the version (`based --version`), embedded or standalone mode, database,
impact, and the smallest reproduction you can make with made-up data. Do not send
live credentials or database dumps. If you are unsure whether something is
sensitive, report it privately.

Handling is best effort, with no fixed response time. Fixes target the latest
release; see [upgrading](book/src/upgrading.md).
